請依照同一資料夾內的 `SPEC.md`、`supabase_schema.sql` 與 `README.md`，開發「股票買賣與損益管理小幫手」個人自用 Web App。

請遵守以下順序：
1. 先檢查目前工作目錄、所有現有檔案、Git 狀態及是否已有 Supabase schema；不得覆蓋未知檔案。若有既有專案，先備份並回報。
2. 先摘要理解的需求、列出任何規格衝突／必要缺口，並檢查 SQL 範本。不要自行增加商業功能。
3. 先提供檔案計畫與資料庫變更摘要；未經使用者確認，不要對真實 Supabase 資料庫執行破壞性 migration 或刪除資料。
4. 按 `SPEC.md` 開發，採繁體中文、莫蘭迪色系、奶茶色暖背景、大字體、圓角卡片、3D 黏土風格圖示；手機／平板底部導覽、桌面左側導覽。
5. Google 登入、RLS 個人資料隔離、交易記帳、加權平均成本、超額賣出阻擋、歷史交易修改／刪除後重算、持倉、月／年報表、收盤價更新、跨裝置同步均按規格完成。
6. 不可將 Supabase service_role key 放入前端；不可建立公開讀寫 RLS policy。
7. 先以假資料與測試案例驗證，未通過 T01–T12 不要宣稱完成。
8. 完成每個階段後，回報：完成項目、測試及結果、尚未完成、需要使用者親自設定的事項。使用者是非程式背景，操作說明請用繁體中文、逐步且精簡。
9. 不要把真實投資資料放進測試資料或公開 repository。不要擅自部署到公開網址；先完成本地驗收並取得使用者同意後再部署。
