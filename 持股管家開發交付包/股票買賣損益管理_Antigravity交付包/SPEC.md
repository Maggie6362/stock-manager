# 股票買賣與損益管理小幫手 — Antigravity 開發交付規格

版本：1.0  
狀態：可開始實作  
用途：個人自用，不公開販售  
語言：繁體中文（台灣）  
核心原則：簡單、低成本、跨裝置、易維護；不做商業化擴充。

## 1. 開發目標
建立一個可在 Windows 電腦、iPhone、iPad 使用的響應式 Web App，管理多個證券帳戶的買賣紀錄、持倉、加權平均成本、每日收盤價、未實現損益，以及月度／年度已實現損益。

## 2. 已確認的使用者決策
- 個人自用，沒有公開販售或多使用者商業服務需求。
- 登入方式：Google 登入。
- 首頁：推薦資訊密度，顯示四項核心統計、持倉摘要、常用操作。
- 導覽：iPhone/iPad 使用底部導覽；電腦使用左側導覽。
- 視覺：繁體中文、莫蘭迪色系、奶茶色暖背景、大字體、圓角卡片、簡潔導覽、柔和陰影、3D 黏土風格圖示。
- 跨裝置：同一 Google 帳號在電腦、iPhone、iPad 登入後，資料應同步。
- 帳戶成本：各證券帳戶獨立計算加權平均成本；整合畫面只合併呈現總計，不跨帳戶混算成本。
- 超額賣出：若該帳戶該股票庫存不足，禁止儲存並提示。
- 歷史交易：允許修改與刪除；交易異動後重新計算受影響的後續庫存、成本與損益。
- 以每日收盤行情為準，不提供盤中即時報價。
- 不處理自動配股配息追蹤。
- 優先零成本；不得因零成本而省略必要的登入、資料隔離與備份措施。

## 3. 建議技術方案
- 前端：單一 `index.html` 或輕量靜態前端；優先選擇最容易維護、適合初學者交接的方案。
- 部署：GitHub Pages（若 Google OAuth 回呼與部署限制需要調整，可選同樣免費的靜態託管替代方案，但須先說明）。
- 後端資料庫與登入：Supabase Auth + PostgreSQL + RLS。
- 行情：TWSE OpenAPI `https://openapi.twse.com.tw/v1/exchangeReport/STOCK_DAY_ALL`，收盤後手動按「更新收盤價」批次更新；需處理來源暫時不可用、代號未匹配與資料日期提示。
- 不得將 Supabase `service_role` key 放在前端。前端只可使用 Supabase URL 與 anon/publishable key，並依 RLS 限制存取。
- Supabase 免費方案與行情 API 的限制需在 README 說明；不得保證第三方服務永久免費或永久可用。

## 4. 頁面與導覽
### 4.1 登入頁
- Google 登入。
- 未登入只可看到登入頁，不能讀取帳戶或交易資料。
- 顯示簡短產品名稱與登入狀態；避免多餘介紹頁。

### 4.2 首頁／資產看板
- 帳戶篩選：單選、複選、全選。變更選取後，持倉與損益即時重新計算。
- 四大統計卡片：
  1. 在庫總成本
  2. 未實現總損益
  3. 當年度已實現損益
  4. 累計稅費
- 顯示精簡持倉摘要及「新增交易」「查看持倉」「損益報表」入口。
- 清楚顯示收盤價資料日期／最後更新狀態。不可把示意數值當真實資料。
- 金額使用新台幣格式；損益以正負值與文字共同呈現，不只依賴顏色。

### 4.3 交易記錄
- 可新增、編輯、刪除交易。
- 可按帳戶、日期區間、股票代號篩選。
- 欄位：帳戶、交易日期、買入／賣出、股票代號、股票名稱、股數、成交單價、手續費、證交稅。
- 必填：帳戶、日期、買賣別、股票代號、股票名稱、股數、單價。
- 股數及單價必須大於 0；股數使用整數。
- 預設手續費：`max(20, floor(成交金額 * 0.001425))`。
- 預設證交稅：買入為 0；賣出 `floor(成交金額 * 0.003)`。
- 允許覆寫實際手續費及稅金。費率僅為預設估算，不可聲稱涵蓋所有券商折扣或特殊稅制。
- 刪除或修改交易前顯示清楚確認／儲存提示。

### 4.4 新增／編輯交易表單
- 手機單欄、平板／電腦可合理使用雙欄。
- 選擇帳戶、日期、買賣別、股票代號、名稱、股數、單價、手續費、證交稅。
- 顯示成交金額與預估稅費。
- 賣出時先依同帳戶、同股票及交易排序後的庫存檢查是否足夠；不足時禁止儲存並顯示可用股數。
- 編輯歷史交易時，先排除舊版本交易，再檢查修改後的完整交易序列是否仍合理。

### 4.5 持倉總覽
- 以「帳戶 + 股票代號」作為獨立持倉計算單位。
- 欄位：帳戶、股票代號、股票名稱、剩餘股數、加權平均成本／股、剩餘總成本、參考收盤價、未實現損益、未實現報酬率。
- 支援帳戶篩選與整合顯示。
- 提供「更新收盤價」按鈕與「手動修改參考價格」功能。
- 手動參考價需清楚標示為手動資料及更新時間；不得假裝是交易所最新收盤價。

### 4.6 損益報表
- 月度已實現損益：依賣出成交日所屬月份分組。
- 年度已實現損益：依當年度 1–12 月彙總。
- 顯示已實現損益、賣出總金額、交易稅費。
- 可依帳戶篩選或整合呈現。
- 圖表為輔助，表格數字才是精確核對依據。

### 4.7 帳戶管理
- 初始提供帳戶1、帳戶2、帳戶3、帳戶4。
- 可新增、重新命名、刪除帳戶。
- 刪除含交易紀錄的帳戶時，必須顯示明確警告與影響；不要靜默連帶刪除交易。
- 建議預設不允許直接刪除有交易的帳戶；提供先備份、先處理交易紀錄的明確流程。
- 帳戶名稱唯一性應限制在同一使用者範圍內。

## 5. 損益計算規格
### 5.1 計算隔離
- 每個使用者的每個帳戶、每檔股票獨立計算。
- 帳戶整合只將各帳戶已算好的數值加總；不得把帳戶 A 的買入拿去降低帳戶 B 的成本。
- 同帳戶同股票的交易依交易日期升冪排序；同一天交易需有穩定且可重現的順序（建議 created_at，必要時加入交易序號）。若同日買賣的先後順序影響庫存，介面應讓使用者確認或以明確序號決定，不能任意排序。

### 5.2 買入
- 買入總成本增加：股數 × 單價 + 實際手續費。
- 新總股數 = 原股數 + 買入股數。
- 新總成本 = 原總成本 + 買入總成本。
- 加權平均成本／股 = 新總成本 ÷ 新總股數。

### 5.3 賣出
- 賣出前必須有足夠庫存。
- 平倉成本 = 賣出股數 × 當下加權平均成本／股。
- 賣出淨額 = 股數 × 單價 − 實際手續費 − 實際證交稅。
- 已實現損益 = 賣出淨額 − 平倉成本。
- 剩餘總成本 = 原總成本 − 平倉成本。
- 剩餘股數 = 原股數 − 賣出股數。
- 全部賣出後剩餘股數與成本歸零；避免浮點誤差導致負零。

### 5.4 未實現損益
- 參考市值 = 收盤價 × 剩餘股數。
- 預估賣出手續費 = `max(20, floor(參考市值 * 0.001425))`。
- 預估賣出證交稅 = `floor(參考市值 * 0.003)`。
- 未實現損益 = 參考市值 − 預估賣出手續費 − 預估賣出證交稅 − 剩餘總成本。
- 未實現報酬率 = 未實現損益 ÷ 剩餘總成本 × 100%。
- 若無收盤價，顯示「尚無收盤價」，不得當作 0 元或計算出誤導性損益。
- 若剩餘成本為 0，報酬率顯示「—」。

### 5.5 交易編輯／刪除後重算
- 不把計算結果作為唯一真實來源；交易流水為來源，持倉與損益由交易流水重新計算。
- 編輯／刪除一筆交易後，重新計算該帳戶該股票全部受影響交易序列。
- 若修改後造成任何賣出時庫存不足，拒絕儲存並說明哪筆交易及缺少股數。
- 使用金額計算時盡量使用整數／精確小數處理，避免二進位浮點誤差。

## 6. 資料表與安全
### 6.1 建議資料表
1. `profiles`：`id`（與 Supabase Auth user id 相同）、`created_at`。
2. `accounts`：`id` UUID、`user_id` UUID、`name`、`created_at`；同一使用者內名稱唯一。
3. `transactions`：`id` UUID、`user_id` UUID、`account_id` UUID、`stock_id`、`stock_name`、`trade_date`、`action_type`（BUY/SELL）、`shares`、`price`、`fee`、`tax`、`created_at`、可選 `updated_at`。
4. `prices`（可選但建議）：`stock_id`、`stock_name`、`close_price`、`price_date`、`source`（TWSE/MANUAL）、`updated_at`。若採用每個帳戶同股票共用參考收盤價，須避免各帳戶產生不一致的官方行情；手動價格的適用範圍需在介面明確說明。

### 6.2 必要安全規則
- 使用 Supabase Auth Google OAuth。
- `accounts`、`transactions` 啟用 RLS。
- 使用者只能對 `user_id = auth.uid()` 的資料進行 SELECT/INSERT/UPDATE/DELETE。
- `transactions` 必須驗證其 `account_id` 屬於同一 `user_id`，防止跨使用者帳戶引用。
- 若使用 `profiles`，使用者只能讀寫自己的 profile。
- 不使用 `USING (true)` / `WITH CHECK (true)` 公開讀寫政策。
- 不在前端放 `service_role` key、資料庫密碼或任何管理密鑰。
- Google OAuth redirect URL 僅允許正式與必要測試網域。
- 未登入狀態不得載入個人資料。
- 本 App 是個人自用，但不得把網站公開網址等同於資料可公開讀寫。

## 7. 跨裝置與介面驗收
- 電腦、iPhone、iPad 使用同一帳號後可讀到同一資料。
- 在裝置 A 新增一筆交易，裝置 B 重新載入或重新取得資料後能看到；修改與刪除同樣驗證。
- 不要求複雜即時推播；簡單可靠的重新載入／重新取得資料即可，若容易實作可使用 Supabase Realtime。
- iPhone 直向不得出現重要按鈕被遮擋或表單輸入導致頁面不合理放大；互動元素須有足夠觸控尺寸。
- iPad 直向／橫向、桌面寬螢幕皆需合理排版。
- 導覽：手機／平板底部導覽；桌面左側導覽。
- 文字繁體中文、數字易讀、正負損益除顏色外需有 +／− 與文字。
- 需顯示收盤行情資料日期與更新狀態。

## 8. 最低驗收測試案例
### T01 登入與資料隔離
- 未登入不能進入功能頁。
- 登入後只可讀寫本人帳戶與交易。
- 嘗試讀取其他 user_id 的資料應被 RLS 拒絕。

### T02 買入加權平均成本
- 同帳戶同股票：買入 100 股 × 100 元，手續費 20；再買 100 股 × 120 元，手續費 20。
- 預期總股數 200；總成本 22,040 元；平均成本 110.20 元。

### T03 部分賣出
- 接續 T02，賣出 50 股 × 130 元，手續費 20，證交稅 19（按規格輸入實際稅額）。
- 平倉成本 5,510 元；賣出淨額 6,461 元；已實現損益 951 元。
- 剩餘股數 150；剩餘成本 16,530 元。

### T04 超額賣出
- 庫存 100 股，嘗試賣出 101 股。
- 預期拒絕儲存並顯示可用股數 100。

### T05 跨帳戶隔離
- 帳戶 A 買入 100 股、帳戶 B 買入同股票 100 股但成本不同。
- 預期各自平均成本分開；整合畫面只加總庫存、成本及損益。

### T06 修改歷史買入
- 修改早期買入價格或股數。
- 預期重新計算後續交易；若使後續賣出超額則拒絕儲存。

### T07 刪除歷史交易
- 刪除一筆買入交易。
- 預期重算同帳戶同股票所有後續交易；若造成庫存不足，拒絕刪除並提示。

### T08 未實現損益
- 有收盤價時，按參考市值扣除預估賣出稅費與剩餘成本計算。
- 無收盤價時顯示「尚無收盤價」，不以零價計算。

### T09 月度／年度報表
- 按賣出成交日歸屬月份，月度加總已實現損益、賣出總額與稅費；年度總計與月份加總一致。

### T10 收盤價更新
- API 成功時更新對應股票價格與日期。
- API 失敗時保留最後有效資料並顯示錯誤／最後更新時間，不清空價格。
- 無法匹配的股票顯示明確狀態。

### T11 跨裝置同步
- 在電腦新增交易，在 iPhone 與 iPad 登入同帳號後能看到。
- 在 iPhone 修改交易後，電腦重新載入後顯示新資料。
- 不同使用者資料不能互相可見。

### T12 響應式與易用性
- iPhone 直向、iPad 直向／橫向、桌面寬螢幕主要頁面均可操作。
- 無橫向溢出造成核心按鈕無法使用；持倉表格可採卡片或容器內橫向捲動。
- 導覽位置符合裝置規則，繁體中文字體清晰。

## 9. 開發順序（簡化）
1. 先檢查交付資料及目前是否已有程式／Supabase 專案；不得覆蓋未知的現有檔案。
2. 建立安全的 Supabase schema、RLS 與 Google OAuth 設定說明。
3. 實作登入、導覽與響應式視覺。
4. 實作帳戶與交易 CRUD、交易序列驗證及損益計算。
5. 實作持倉、報表、收盤價更新。
6. 依 T01–T12 測試；修正後再部署。
7. 提供簡明繁體中文 README，逐步列出使用者必須親自完成的 Supabase、Google OAuth 與部署操作；不要要求使用者自行手動改多個檔案，能自動化的盡量自動化。

## 10. Antigravity 執行指示
- 先閱讀本規格與原始規格，列出任何衝突或缺口；不要自行擴增商業功能。
- 在開始改動前先檢查工作目錄、現有程式與 Git 狀態；有既有內容先備份。
- 先產生可審查的 SQL migration 與檔案清單，再實作。
- 不可在前端暴露 service_role key。
- 不可建立公開讀寫 RLS policy。
- 不可聲稱已完成 Google OAuth、跨裝置同步或行情串接，除非已實際設定並通過測試。
- 每個階段回報完成內容、測試結果、未完成項目及使用者需要操作的步驟。
- 未經使用者確認，不要對真實資料庫執行破壞性 migration，不要刪除既有資料。
